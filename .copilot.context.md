
# FERP Message Library — Copilot Context

## Project Overview

This is the **ferp-message-library** monorepo — a shared C++ message/module library
for the **ferp-com** product: a fuel-dispenser communication controller built on ESP32.

The codebase is structured as a portable library (HSYS framework) with a product layer
on top (`ferp-com-main`). It targets two build environments:
- **ESP32 (production)** — compiled with ESP-IDF v5.5
- **macOS Simulator** — native binary via CMake + AppleClang for development/testing

## Architecture

### Layer Stack (top → bottom)

```
Application Layer  (app.cpp, product modules, msg translators)
App Modules        (module_wifi, module_fuel, module_mqtt, …)
App Messages       (MsgConfigWifi, MsgFuelPumped, IHsysMsg, …)
HSYS Framework     (HsysModule, hsys_msg_t, hsys_pool, hsys_task_mgr)
HSYS OS            (hsys_task, hsys_queue, hsys_mutex, hsys_semaphore)
PAL                (pal_wifi, pal_mqtt, pal_gpio, pal_spiffs, pal_fw_update)
Platform           ESP-IDF  |  macOS (simulator)
```

### Message System
- All messages inherit from `IHsysMsg` (see `src/app-messages/IHsysMsg.h`)
- Each message declares a static `ID` (uint16), a `Payload` struct, and
  implements `serialize()` / static `deserialize()` / `create()` / `from_json()` / `to_json()`
- Messages are carried as `hsys_msg_t*` pool-allocated objects on the bus
- JSON ↔ `hsys_msg_t` codec is registered in `product/app/app.cpp`
- Wire envelope: `{ "seq": <uint32>, "msg": "<ClassName>", "data": { … } }`

### Module System
- All modules inherit from `HsysModule` (ID + name, lifecycle: `pre_init` → `init` → `post_init`)
- Runtime: `on_msg_received(const hsys_msg_t &msg)` dispatch loop
- Modules subscribe to message IDs in `init()`; publish via `publish()` / direct-send

## Recent Changes (last 3 commits: `6b040f2` → `852b7db`)

### 1. MQTT Authentication (`mqtt_auth.h` / `mqtt_auth.py`)
Protects public-broker MQTT commands from MITM by adding a keyed hash to every inbound cmd envelope.

**Extended envelope fields:**
```json
{ "seq": 42, "msg": "MsgConfigSet", "data": {...},
  "hop_idx": 3, "hash": "a1b2c3d4e5f60718" }
```
- `hop_idx` (0–15) selects a row from a 16-entry 64-bit key table
- `hash` = splitmix64-style `mqtt_auth_hash(keys[hop_idx], seq)` rendered as 16-char hex
- Key table is identical in `src/app-modules/module_mqtt/mqtt_auth.h` and `tools/ferp-device-tool/mqtt_auth.py`
- Verified in `ModuleMqtt::on_msg_received()` before dispatching any command

### 2. MsgConfigUpdated — live config change notification
New message (`src/app-messages/configs/msg_config_updated.h/.cpp`) published by `ModuleConfig` after any `MsgConfigSet` write.

- Payload: `uint16_t key` — the `CFG_KEY_*` constant that changed
- Subscribers check the key and call `app_config_get()` if relevant
- Registered in `app_msg_table.h` and `app_msg_ids.h`
- **Use case:** `ModuleFuel` re-reads `CFG_KEY_DT_LOG_RATE` dynamically without reboot

### 3. ModuleUdpLog (ID 27) + pal_udp_log
New module that streams log output to a UDP server over WiFi — useful for remote debugging without serial cable.

| File | Purpose |
|------|---------|
| `src/app-modules/module_udp_log/ModuleUdpLog.h/.cpp` | Module; registers `pal_udp_log_sink` with `pal_logger` |
| `src/sub-modules/pal/pal_udp_log.h` | PAL interface (`pal_udp_log_init/start/stop/send`) |
| `src/sub-modules/pal/pal_udp_log.h` | PAL interface |
| `src/sub-modules/pal/esp-idf/pal_esp_idf_udp_log.cpp` | ESP-IDF impl |
| `src/sub-modules/pal/mac-pc/pal_mac_udp_log.cpp` | macOS simulator impl |
| `src/sub-modules/pal/pal_logger.h` | Extended with multi-sink registration API |
| `helper-scripts/udp-script.py` | Python UDP log receiver (desktop debugging) |
| `helper-scripts/udp-debug.py` | Minimal UDP debug listener |

**Lifecycle:**
1. `MsgConfigReady` → reads `en_udp_ser`, `udp_srvr_ip`, `udp_srvr_port` → `pal_udp_log_init()`
2. `MsgWifiEvent(GOT_IP)` → strips colons from MAC → `pal_udp_log_start()` → registers sink
3. `MsgWifiEvent(DISCONNECTED)` → unregisters sink → `pal_udp_log_stop()`

**Config keys required:** `en_udp_ser` (bool), `udp_srvr_ip` (string), `udp_srvr_port` (uint32)

### 4. ModuleFuel — additional pump protocols
`ModuleFuel` extended to support **sanki6** and **cen6** pump state machines alongside the existing DispTap protocol. Pin IDs moved to a dedicated `app_hw.h` file.

## Build Commands

### ESP32 (IDF v5.5)

```bash
# Activate ESP-IDF environment (run once per terminal session)
source '/Users/chathurangadissanayaka/.espressif/tools/activate_idf_v5.5.3.sh'

# Build firmware
cd src/product/ferp-com-main/ferp-com-esp32-idf
idf.py build

# Flash + monitor
idf.py flash monitor

# Flash SPIFFS partition only
idf.py -p /dev/cu.usbserial-XXXX spiffs-flash
```

### macOS Simulator

```bash
cd src/product/ferp-com-main/ferp-com-simulator
./build.sh          # cmake + make
./run.mac.sh        # run simulator (TCP bridge :9000, HTTP config :8080)
```

### Device Tool (Python GUI)

```bash
cd tools/ferp-device-tool
./run.mac.sh        # macOS launcher (activates venv, runs main.py)
# Supports: MQTT transport, WebAPI (HTTP), UART
```
