
# FERP Message Library — Copilot Context

## Project Overview

This is the **ferp-message-library** monorepo — the shared C++ firmware for the
**ferp-com** product: a fuel-dispenser communication controller built on ESP32.

It is structured as a portable multi-layer library (HSYS framework + PAL) with a
product-specific layer on top. Targets two build environments:
- **ESP32-IDF v5.5** — production firmware (`idf.py build / flash`)
- **macOS Simulator** — native CMake binary for development/testing without hardware

## HSYS Framework Deep Dive

### Startup Sequence
```
main()
  ├─ app_platform_pre_init()       platform hook (sim: socket, logger)
  ├─ ModuleMsgTranslator::set_table()
  ├─ app_config_init()             load defaults
  ├─ hsys_pool_init()              static buffer pool
  ├─ hsys_module_init()            register all modules from k_module_table
  ├─ hsys_msg_init()               bus + descriptor table
  └─ hsys_task_mgr_init()          create RTOS tasks from k_task_table
       └─ each task dispatch loop:
            phase 1: pre_init()    (all modules, all tasks → cross-task barrier)
            phase 2: init()        (subscribe → barrier)
            phase 3: post_init()   (publish first one-shots → barrier)
            loop:    dequeue → dispatch → release
```
All three phases complete **globally** before any task enters its message loop.

### Message Lifecycle (zero-copy fan-out)
```
Publisher                  Bus                    Subscriber(s)
  create_typed<T>()
  pool_alloc()
  publish(msg) ──────────► stamp ref_count = N
                            enqueue to each subscriber ──────────►
                                                    on_msg_received()
                                                    hsys_msg_release()
                            ref_count-- per delivery
                            pool_free() when == 0
```
**Zero-copy · Ref-counted · Static pool (no heap at runtime) · Thread-safe**

### Message Types
| Type | Routing | Typical use |
|------|---------|-------------|
| `HSYS_MSG_NOTIFICATION` | All subscribers | Events, status changes |
| `HSYS_MSG_DIRECT` | One specific module | Request / response pairs |

### Ticker
Generates `MsgTick1000ms` every 1 s via soft-timer. No subscriptions.

### ModuleSysmon
Subscribes to `MsgTick1000ms`; logs pool diagnostics every 5 ticks (5 s).

### ModuleSpiffs / ModuleSD
Mount in `pre_init()`. Publish `MsgSpiffsReady` / `MsgSdReady` + `MsgSdStatus` in `post_init()`.

### ModuleConfig
- Loads `Configs/DeviceConfigs.json` on `MsgSpiffsReady`, merges defaults, saves back
- Publishes `MsgConfigReady`
- Responds to `MsgConfigGet*` with DIRECT typed responses
- On `MsgConfigSet` → updates RAM + file → publishes `MsgConfigUpdated(key)`
- Subscribers react to `MsgConfigUpdated` to pick up live changes without reboot

### ModuleTimer
Software timer service. Max 20 slots; resolution ±100 ms; one slot per `source_module_id`.
`MsgTimerStart` → `MsgTimerStartResponse` (DIRECT) + `MsgTimerAlarm` (DIRECT on expiry).

### ModuleWifi
State: `WAIT_FOR_CONFIG → CONNECTING → CONNECTED → RECONNECTING`.
Retry interval: 10 000 ms. Publishes `MsgWifiEvent(GOT_IP / DISCONNECTED)`.

### ModuleInternet
Pings `8.8.8.8` every 60 s after GOT_IP. Publishes `MsgInternetStatus` on state change only.

### ModuleTimeMgr
Cascaded time sources: **SPIFFS backup → DS1307 RTC (I²C addr 0x68) → NTP**
- Each source sets `settimeofday()` and tries the next better source in background
- Publishes `MsgTimeStatus(source, valid, epoch)` on every transition
- SPIFFS backup: `/timemgr.bin` (raw `time_t`, 8 B); max 1 write per 300 s
- NTP triggered by `MsgInternetStatus(connected=true)`; re-syncs on reconnect
- **Simulator:** NTP = no-op (host time used); DS1307 = in-process emulator (`ds1307_i2c_emulator.cpp`)

### ModuleFuel
High-frequency dispenser data bypasses the bus intentionally:
```
DT serial driver (ISR context)
  └─ _on_distap_frame() → queue to _frame_queue[n] → wake()
       └─ on_wake() (fuel_task)
            FuelDispTapDriver: WAIT_CONFIG→RESETTING→FW_UPDATE→RUNNING
            FuelSankiProcessor::push_frame() (direct call — not on bus)
            GPIO nozzle edge → hsys_tog_button_t debounce (500 ms)
            → event-group bits → sanki6_process_state_machine()
            → Pumping_State_Stopped → publish MsgFuelPumped + MsgNozzleState
```
Nozzle GPIO events handled via `hsys_event_group_t` bits — **never on the message bus**.
Protocols supported: **DispTap/Sanki6, Cen6, Wayne**

Simulator injection via TCP JSON:
```json
{ "cmd": "SIM_DISTAP_FRAME", "nozzle": 0, "unit_price": 300, "volume_l": 500 }
{ "cmd": "SIM_NOZZLE_INPUT", "nozzle": 0, "active": true }
```

### ModuleCubeSphere (cloud backend, ID 13)
Manages HTTPS communication with CubeSphere cloud.

**Event types (`evt_type_t`):**
| Event | Cloud endpoint | Status |
|-------|---------------|--------|
| `EVT_STARTUP` | `app.device/startup` | ✅ |
| `EVT_RECONNECT` | `app.device/reconnect` | ✅ |
| `EVT_HEARTBEAT` | `app.device/heartbeat` | ✅ |
| `EVT_PUMPED` | `app.fuel/pump-end` | ✅ |
| `EVT_PUMPED_RETX` | `app.fuel/pump-end` (retry) | ✅ |
| `EVT_TOTALIZED` | `app.fuel/totalized` | WIP |
| `EVT_PUMP_START` | `app.fuel/pump-start` | WIP |
| `EVT_PRINT_OK` | `app.fuel/printok` | WIP |
| `EVT_STATUS_UPDATE` | `app.device/status` | ✅ |

HTTP sessions go via ModuleHttp (DIRECT message burst). Failed events are
persisted to SD card via `RetransmissionManager` and replayed on each heartbeat tick (60 s).

**Retransmission storage:** `/sd/retx/evt_YYYYMMDD.txt`, line-per-event, 7-day retention.

**Known limitation:** Live-send HTTP failures (non-2xx) are NOT persisted to retx —
only the early-reject path (not RUNNING / HTTP busy) writes to retx. The `send_callback`
in `_retx_init` is a TODO stub.

### ModuleHttp
Single-session HTTPS client. Only one session at a time.
Full exchange: `MsgHttpStartRequest → MsgHttpStartResponse → [SetRootCA, SetUrl, Headers, Body, Send] → MsgHttpResult`

### ModuleMqtt (ID 22)
MQTT bridge + OTA source.
- Topic: `ferp/{dev-type}/{group}/{device_id}/cmd|resp|evt|ota/ctrl|data|resp`
- Subscribes to 3 patterns (device-specific, group, group-type-wildcard)
- MQTT callback: copy payload to static buffer + set event bit (ISR-safe); decode in module task
- Inbound: JSON → `app_msg_codec_decode()` → dispatch on bus
- Outbound: application DIRECT responses → `app_msg_codec_encode()` → publish on `.../resp`
- `seq` from inbound cmd stored keyed by response `msg_id`; echoed back in resp envelope
- **Auth:** every inbound cmd must include `hop_idx` + `hash` (splitmix64); verified via
  `mqtt_auth_verify()` before dispatch (see `mqtt_auth.h`)
- OTA binary chunks on `.../ota/data` bypass the message pool — streamed via `ota_fs_driver_t`

### ModuleUdpLog (ID 27)
Streams log output to a UDP server over WiFi. No-op on macOS simulator.
1. `MsgConfigReady` → `pal_udp_log_init(server_ip, port, mac_no_colon, wake_fn)`
2. `MsgWifiEvent(GOT_IP)` → `pal_udp_log_start()` → `pal_logger_register_sink(pal_udp_log_sink)`
3. `MsgWifiEvent(DISCONNECTED)` → unregister sink → `pal_udp_log_stop()`
4. `on_wake()` → `pal_udp_log_drain()` — sends queued ≤256-byte entries via UDP

Desktop receiver: `helper-scripts/udp-script.py`

### ModuleMsgTranslator
Rule-table-driven transformer. Decouples modules.
- Table: `{ in_msg_id, in_src, out_msg_id, out_dest, translator_fn, delayed, delay_ms }`
- Set via `ModuleMsgTranslator::set_table()` before `app_init()`
- Add rules in `app.cpp` (`k_translator_table[]`) and implement in `msg_translators.cpp`

### OtaModule (ID 18)
Session gatekeeper only — never touches binary data.
- State: `IDLE → PENDING → ACTIVE → COMPLETING → IDLE`
- On abort/timeout: `driver->ferase(ctx)` then return to IDLE
- On COMPLETE: publish `MsgOtaEvent(COMPLETE)` then `pal_power_reset()` if `needs_reboot`
- Inactivity timer resets on each `MsgOtaProgress`; abort if no progress within `timeout_ms`

## OTA System

### Targets
| idx | Label | Backend | Reboot |
|-----|-------|---------|--------|
| 0 | `esp32-main` | `esp_ota_begin/write/end/set_boot_partition` | Yes |
| 1 | `esp07-disptap` | Stage to `/ota_esp07.bin` on SPIFFS; UART flash via `start_serial_flash()` | No |

### `ota_fs_driver_t` Interface
```c
fopen(ctx, path, mode)  // prepare write target
fwrite(ctx, data, len)  // stream chunk
fappend(ctx, data, len) // append variant
fclose(ctx)             // commit
ferase(ctx)             // abort / cleanup
fread(ctx, buf, len)    // optional read-back
```

### OTA over MQTT
```
.../ota/ctrl  ota_start { target, size, version, crc32 }
.../ota/data  [OFFSET 4B BE][RAW CHUNK]   (max 4 KB recommended)
.../ota/ctrl  ota_complete { crc32 }
.../ota/resp  { cmd, status, offset_next }
```

## MQTT JSON Protocol

### Envelope (all three topic kinds share the same structure)
```json
{ "seq": 42, "msg": "MsgConfigSet", "data": { "key": "mqtt_host", "type": "string", "value": "broker.local" } }
```

### Auth extension (cmd only)
```json
{ "seq": 42, "msg": "...", "data": {...}, "hop_idx": 3, "hash": "a1b2c3d4e5f60718" }
```
`hash` = splitmix64-keyed hash of `seq` using `k_mqtt_auth_keys[hop_idx]`.
**Must stay in sync:** C → `mqtt_auth.h`, Python → `mqtt_auth.py`

### Adding a message to the JSON interface
1. Add `from_json()` and `to_json()` to the message `.cpp`/`.h`
2. `#include` it at top of `app.cpp`
3. Add a row to `k_codec_table[]` in `app.cpp`

## How to Add a New Message — Complete Checklist

Every new message type touches **8 locations** (10 if it needs MQTT/WebAPI routing).
Miss any one of them and the build will fail or the message will be silently dropped.

### 1. Assign a message ID
Edit `src/product/ferp-com-main/app/app_msg_ids.h`:
```cpp
MSG_ID_MY_CMD  = 0x0XYZ,   // must be < HSYS_MAX_MSG_IDS (1024)
MSG_ID_MY_RESP = 0x0XYZ+1,
```

### 2. Create the message header
`src/app-messages/<domain>/msg_my_cmd.h`:
```cpp
#pragma once
#include "IHsysMsg.h"

class MsgMyCmd {
public:
    static constexpr hsys_msg_id_t ID = MSG_ID_MY_CMD;
    static const hsys_msg_desc_t   DESCRIPTOR;

    struct Payload { /* fields */ };

    static hsys_msg_t *create(hsys_module_id_t sender_id /*, args */);
    static const Payload *get_payload(const hsys_msg_t *msg);
    static hsys_msg_t *from_json(const char *data_json, hsys_module_id_t sender_id);
    static int         to_json  (const hsys_msg_t *msg, char *buf, size_t len);
};
```

### 3. Create the message source file
`src/app-messages/<domain>/msg_my_cmd.cpp`:
```cpp
#define __TAG__  "MYTAG___"   // EXACTLY 8 characters — enforced by _Static_assert
#include "msg_my_cmd.h"
#include <ArduinoJson.h>

const hsys_msg_desc_t MsgMyCmd::DESCRIPTOR =
    HSYS_MSG_DESC(MSG_ID_MY_CMD, HSYS_MSG_NOTIFICATION, sizeof(Payload),
                  HSYS_PERM_ANY, HSYS_PERM_ANY);

hsys_msg_t *MsgMyCmd::create(hsys_module_id_t sender_id) {
    hsys_msg_t *msg = hsys_msg_create(ID, sender_id);
    if (!msg) return nullptr;
    auto *p = static_cast<Payload *>(msg->payload);
    // fill p->...
    return msg;
}
```
`to_json` uses `StaticJsonDocument<N>` then `serializeJson()`; `from_json` parses with
`deserializeJson()` then calls `create()`.

### 4. Register in the descriptor table
Edit `src/product/ferp-com-main/app/app_msg_table.h`:
- Add `#include "msg_my_cmd.h"` in the includes block.
- Add `MsgMyCmd::DESCRIPTOR,` inside `APP_MSG_TABLE_INIT`.

> ⚠️ **HSYS_MAX_REGISTERED_MSGS** — the table size is validated at runtime in
> `hsys_msg_table_init()`. If the count exceeds the limit the **entire table is
> silently rejected** and every `hsys_msg_create()` call fails with
> `"create: unknown msg_id"`. The limit is set in
> `src/product/ferp-com-main/app/user_config.h`. Bump it (and update the comment)
> whenever you add messages that would exceed it. As of 2026-05-18: **65 messages
> registered, limit = 80**.

### 5. Add to both CMakeLists.txt files
**ESP32 target** — `src/product/ferp-com-main/ferp-com-esp32-idf/main/CMakeLists.txt`:
```cmake
"${D_MSGS}/<domain>/msg_my_cmd.cpp"
```
**Simulator target** — `src/product/ferp-com-main/ferp-com-simulator/CMakeLists.txt`:
```cmake
${APP_MSGS}/<domain>/msg_my_cmd.cpp
```
Omitting either produces **linker errors** (undefined reference to `MsgMyCmd::create`, etc.).

### 6. Register in the JSON codec (if MQTT/WebAPI accessible)
In `src/product/ferp-com-main/app/app.cpp`, add `#include` at top, then add a row:
```cpp
{ "MsgMyCmd", MSG_ID_MY_CMD, MsgMyCmd::from_json, MsgMyCmd::to_json },
```

### 7. Register MQTT route (inbound commands)
In `app.cpp`, `k_mqtt_route_table[]`:
```cpp
{ MSG_ID_MY_CMD, (hsys_module_id_t)0, false },   // 0 = broadcast NOTIFICATION
```
ModuleMqtt must also **subscribe to the response** in `ModuleMqtt::init()` and forward
it in the switch statement in `_on_msg_received()`.

### 8. Register WebAPI route (if needed)
In `app.cpp`, `k_api_routes[]`:
```cpp
{ MSG_ID_MY_CMD, (hsys_module_id_t)0, MSG_ID_MY_RESP },
```
ModuleWebServer auto-subscribes to `response_id`; uses a semaphore to wait for the reply.

### 9. Subscribe in the handling module
In the module that processes the message, add `subscribe(MsgMyCmd::ID)` in `init()` and
handle it in `on_msg_received()`.

### 10. Add JSON descriptor files for the device tool
Two identical files (the tool loads both paths):
- `src/app-messages/messages/<Domain>/msg_my_cmd.json`
- `tools/ferp-device-tool/messages-json/<Domain>/msg_my_cmd.json`

Format:
```json
{ "msg_id": "0x0XYZ", "direction": "cmd", "fields": [
    { "name": "my_field", "label": "My Field", "type": "string", "default": "" }
]}
```
`"direction"`: `"cmd"` for commands, `"resp"` for responses, `"notif"` for notifications.

## Dynamic Payload Pattern (inner buffer)

Used when the payload size is **variable or large** (e.g., a JSON string), and the slab
itself is kept fixed-size so the pool class stays predictable.

```
Slab layout (fixed, allocated from pool):
  bytes 0..3   uint32_t  data_len    — length of the inner buffer
  bytes 4..7   uint8_t   _pad[4]     — alignment pad
  bytes 8..11  void     *inner_buf   — pointer to separately pool-alloc'd buffer
```

In `create()`:
```cpp
char *buf = static_cast<char *>(hsys_pool_alloc(data_len + 1));
// store buf pointer at slab offset 8
memcpy(static_cast<uint8_t *>(msg->payload) + 8, &buf, sizeof(void *));
msg->cleanup = _my_msg_cleanup;   // called when ref_count hits 0
```

Cleanup hook:
```cpp
static void _my_msg_cleanup(hsys_msg_t *msg) {
    void *inner_buf = nullptr;
    memcpy(&inner_buf, static_cast<uint8_t *>(msg->payload) + 8, sizeof(void *));
    if (inner_buf) hsys_pool_free(inner_buf);
}
```

Examples using this pattern: `MsgHttpBodyRequest`, `MsgPoolJson`.

## Known Pitfalls

| Symptom | Cause | Fix |
|---------|-------|-----|
| `create: unknown msg_id=0xXXXX` for **all** IDs on boot | `k_msg_table` count > `HSYS_MAX_REGISTERED_MSGS` — `hsys_msg_table_init` rejects the whole table | Increase `HSYS_MAX_REGISTERED_MSGS` in `user_config.h` |
| Compiler error: `"tag must be exactly 8 characters!"` | `#define __TAG__` is not exactly 8 chars | Count characters; pad with `_` if needed (e.g., `"MYTAG___"`) |
| Linker errors: `undefined reference to MsgFoo::create` | `.cpp` file not listed in one or both `CMakeLists.txt` | Add to both ESP32 and simulator CMake source lists |
| Module never receives a message | `subscribe()` not called in `init()` | Add `subscribe(MsgFoo::ID)` in the module's `init()` |
| MQTT inbound command not dispatched | Message not in `k_mqtt_route_table[]`, or auth check fails | Add route entry; verify `hop_idx` + `hash` in the tool |
| WebAPI call hangs | `response_id` not subscribed by ModuleMqtt, or handler module not publishing response | Subscribe + forward in `ModuleMqtt`; check handler module switch |
